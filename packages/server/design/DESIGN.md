# Kofra Security Print: design system

Extracted from prototype k03 (`../kofra-prototypes-20261022/kofra-k03-security-print/index.src.html`), the design the owner picked on 2026-10-23. Every Kofra page (home, drop and publish, transfer, viewer and versions, dashboard, connect your agent) uses this one system. Colour comes only from tokens, and there are two modes: **light** is the original k03 palette and **dark** is Midnight Intaglio. The default is **Auto**, which follows the device's `prefers-color-scheme`. Since 2026-10-23 the other nine colourways are archived (section 3).

The idea: banknotes, passports and share certificates show their proof where you can check it. Kofra prints its proof the same way: verified sender, exact type, size, SHA-256 checksum, expiry, downloads left, and a way to report abuse. Decoration that proves nothing stays out of the way of the text.

## 1. Files and load order (in @dropway/server)

This copy of the design system is the one the product ships. The prototype folder (single-file pages, theme.js, localStorage) was the design study; the rules below are how the live pages implement it.

| File | Role |
|---|---|
| `design/themes.json` | Source of truth: `modes` (light = `original`, dark = `midnight-intaglio`, default Auto), the 26 colour tokens per mode and the 12 `syn-*` syntax tokens. No archived colourways here. |
| `design/css/*.css` | Component CSS written with plain class names as in the prototype. `scripts/build-design.mjs` adds the `k-` prefix to every class (`.btn.ghost` ships as `.k-btn.k-ghost`), except the files listed as `raw` in `bundles.json` (highlight.js classes). |
| `design/bundles.json` | Which files make the **app** bundle (one immutable stylesheet, `/__dropway/ui/kofra-<hash>.css`) and the **site** bundle (inlined on every site-origin page, under 24 KiB, that is 24,576 bytes minified: `siteBudgetBytes`, asserted in bytes by the build and `design-system.test.ts`). |
| `design/fonts/` | The self-hosted woff2 files (unmodified `@fontsource-variable` 5.3.0), `fonts.json` (unicode ranges, metric-matched fallback faces) and the OFL licences. |
| `src/ui/design.generated.ts`, `src/ui/fonts.generated.ts` | Generated by `npm run design:build`. `npm run design:check` (part of `npm test`) fails when they are stale. |
| `src/ui/theme.ts` | Colour mode: the `__Host-dw_theme` cookie, `?theme=`, the metas, `POST /__dropway/theme`. |
| `src/ui/document.ts`, `src/ui/chrome.ts` | The one HTML document writer and the one header, footer and mode switch for every page. |
| `src/ui/motifs.ts` | Seals and plates as pure string generators. Plates are drawn once into static SVG files, one per mode. |
| `test/e2e-design/shots.mjs` | Screenshots of every page in every mode and width, with CSP, console, axe, overflow, mode, font and copy checks per cell. |

Load order on a page: `<html data-theme>` (only for an explicit mode), the `color-scheme` and `theme-color` metas, then the design CSS (a `<link>` on the app origin with the two text fonts preloaded; inline `<style>` on site origins with fonts loaded from the app origin). There is no theme script and no inline script anywhere; no font CDN.

## 3. Modes

| Mode | Scheme | When | Mood |
|---|---|---|---|
| Light | `original` (Original Security Print) | Auto with a light device setting, older browsers, or the user picks Light | Bottle-green engraving on cream note paper, gold hairlines, vermilion serial |
| Dark | `midnight-intaglio` (Midnight Intaglio) | Auto with a dark device setting, or the user picks Dark | Night-blue stock, ice-blue line work, gold seal frame, coral serial |

- **Auto is the default.** Nothing is stored and `<html>` has no `data-theme`; CSS follows `prefers-color-scheme`, live.
- **Light or Dark** (app origin) is the cookie `__Host-dw_theme=light|dark` (`Path=/; Secure; SameSite=Lax; Max-Age=31536000`). The server writes `<html data-theme="light|dark">` and `only light|dark` metas into the first byte, so there is no flash and no script. Choosing Auto deletes the cookie.
- **Links.** `?theme=light|dark|auto` applies to that one response and wins over the cookie; it is never stored.
- **Site origins** (`<slug>.<sites domain>`) never read or set the cookie: they follow Auto in CSS. Pages Kofra generates there (system pages, password gate, listings, viewers) honour `?theme=`; the app's file viewer adds it to viewer URLs only, never to user files. This works the same before and after the sites domain joins the Public Suffix List.
- **Scoped blocks.** `data-theme="light"` or `"dark"` on any element prints that block in one mode: the gallery thumbnails, and the viewer's PDF sheets, which stay paper-white in dark like a real PDF viewer.
- **Archive.** Nine other colourways were retired on 2026-10-23. They are not part of the shipped design (they live only in the design prototype folder) and pages never offer them.

### Standards followed

| Practice | How |
|---|---|
| Follow the OS by default | `@media (prefers-color-scheme: dark)` in `themes.css`; Auto is the default; light is the fallback where the query is unsupported |
| Explicit override | `[data-theme="light"]` / `[data-theme="dark"]` on `<html>`, set only when the user picks one |
| UA colours follow | `<meta name="color-scheme" content="light dark">`, and the CSS `color-scheme` per mode, so form controls, scrollbars and the canvas match. Explicit modes use `only light` / `only dark` so browser auto-darkening can't override the choice |
| Browser UI colour | `<meta name="theme-color">` with a `media` query per mode; `theme-init.js` sets both to the chosen mode when it is explicit |
| No flash | The server renders `data-theme` from the cookie; Auto is pure CSS. No blocking or inline script |
| Accessible control | A form with three submit buttons (Auto, Light, Dark) in a `role="group"` labelled "Colour theme", `aria-pressed` on the current one, visible labels, Tab and Enter/Space, a 2px `focus` ring, pressed state shown by fill and weight, at least 30px tall. Works with no script (it posts to `/__dropway/theme`); where the dashboard script runs it switches in place |
| Live OS switch | CSS recolours itself; the dashboard script listens to `matchMedia('(prefers-color-scheme: dark)')` change events to update the label and fire `kofra:themechange` |
| Artwork | Seals, plates and the guilloche are SVG coloured by token classes, so they redraw in the new palette with no `filter: invert()`. Document previews keep their own paper |
| Contrast | Both modes pass WCAG 2.x AA (`contrast-check.mjs`) |
| Reduced motion | `prefers-reduced-motion: reduce` turns off the seal draw, smooth scroll and transitions |
| Forced colours | `@media (forced-colors: active)` keeps selection (`Highlight`), progress and the engravings (`CanvasText`) visible |
| Progressive enhancement | Without JavaScript every mode works: the switch is a plain form |
| `light-dark()` | Not used: the media-query form above works in every browser with custom properties, and `light-dark()` would need the same fallback anyway |

Each family falls back to metric-matched faces (`design/fonts/fonts.json`), so nothing moves when the web fonts arrive: `<Family> Fallback` over Arial, Georgia and Courier New (and their metric twins Arimo and Liberation Sans, Gelasio, Cousine and Liberation Mono), then ` Fallback B` over DejaVu Sans, DejaVu Serif and DejaVu Sans Mono for systems that only have DejaVu (Linux containers, headless browsers), and `Public Sans Fallback C` over DejaVu Serif for systems with no sans-serif at all. The screenshot harness records which of them the capture machine resolved (`matrix.json` `source.fontEnv`).

Numbers in tables use `font-variant-numeric: tabular-nums`. Write sentence case everywhere. Mono uppercase is only for kickers, serials and stamps.

## 5. Space, radii, borders

- Spacing scale: 4, 8, 12, 16, 20, 24, 32, 44, 56, 64, 72 px (`--s1` to `--s11`). Content width is 1200px with 32px gutters (16px under 720px). Sections are 64px tall (44px on mobile), and the hero is 72/64px.
- Radii: 0 for anything that is paper (documents, plates, stubs, cards, receipts). 3px for stamps and chips, 4px for buttons, inputs and segmented controls, 10px for the email mock, 12px for browser chrome, and 50% for seals and round stamps.
- Borders: 1px `rule` hairlines separate sections and frame paper. 1px `rule-soft` divides rows. 1px `accent` marks things you act on or must read (stub, panel, receipt, state, table head). 2px dashed `rule` is a perforation. 3px double `signal` is a big stamp. 3px left `accent` marks a quote or banner, and 4px left `signal` an annotation. Framed paper adds an inner 1px `rule-soft` line inset 6px (`.card.framed`, `.receipt`).
- Shadows are rare and soft, used only on mock chrome (email, browser) and toasts. In dark the shadow base is black.

## 6. Motifs (all procedural SVG, no raster)

All motif SVG uses classes, never colour attributes. `.e1 .e2 .e3 .em .ef` set the stroke and `.fm .ft .fp .fp0` set the fill. Each class maps to a token, so a mode switch (including a live OS switch in Auto) recolours everything at once without a redraw.

**Guilloche curve.** Each line is a circle with two harmonics: `r(t) = R + A·sin(n·t + φ) + B·sin(m2·n·t − 2φ)`. A band is `cp` copies of the curve with the phase `φ` stepped by `2π/cp`, so the copies interfere into a moiré lattice. Each band is offset by `skew·bandIndex`.

**Transfer seal** (`<svg data-seal="KF-7KQ2-M9XA">`, k03 construction). The seed is FNV-1a of the ID, fed to mulberry32. The draw order is fixed: `B = 1.2 + 2.2r`, `m2 = 2 + ⌊3r⌋`, `skew = πr`, then the four bands:

| Band | R | A | n | copies full/small | class | stroke |
|---|---|---|---|---|---|---|
| outer | 80 | 5 to 8 | 20 to 31 | 12/7 | `e1` | 0.32 (×1.6 when small) |
| second | 61 | 9 to 14 | 9 to 15 | 14/7 | `e1` | 0.32 |
| inner | 40 | 8 to 13 | 6 to 11 | 12/6 | `e2` | 0.32 |
| centre | 18 | 5 to 8 | 5 to 8 | 9/5 | `em` | 0.42 |

The frame is an `ef` ring at r 98 (0.8) plus r 95.5 (0.4), and the dot is `fm` (r 4). The full size adds ring text on r 92.5: the ID, `KOFRA` and the recipient's name in 4.2px Martian Mono (`data-seal-text`). Sizes: `full` (300 points per curve), `small` (180, no ring text, for email, comparisons and receipts), `mini` (120, the first three bands at 3 copies with 3.84 stroke and a thick frame, for 40px file seals). One changed character in the ID gives a completely different seal, and that is the point: the user compares the seal in the email with the one on the page. File seals are seeded from `SHA256:<hex>`. A seal proves the bytes are the ones uploaded. It never means "safe".

**Plate** (`<svg data-plate="seed" data-plate-label="PLATE I">`). This replaces k03's raster intaglio. On a 600×400 field it draws a lathe ground of wavy lines (`e3`), a double `ef` frame, two microtext rows, four corner rosettes (`e1`/`e2`, 8 and 6 copies) and a central five-band rosette (`e1, e1, e2, e2, em`; 16 to 20 copies, 420 points) on a `fp` knockout disc. Add `data-plate-lite` for thumbnails (fewer, thicker lines).

**Guilloche band** (`.guilloche-band`, `.thin`, `.accent`). Six phase-shifted waves in a 40×24 tile, applied as a CSS mask over `background: var(--eng-3)`. Use it as a section divider under the hero and above the footer, at most twice per page.

**Lathe** (`.lathe`). A fine wavy-line ground at 22% `eng-3` behind a positioned block. Use it sparingly, for one hero panel or a receipt.

**Microtext frame** (`.doc[data-micro]` with `.micro.t/.b/.l/.r`). Repeats the recipient's name, transfer code and ID in 4px type around the document, like a passport page. A reused screenshot carries the wrong name.

**Stamps** (`.stamp`, `.bigstamp`, `.grey`, `.quiet`). Rubber-stamp marks for terminal states: Expired, Withdrawn, 3 of 3 used, 451, Held. They are rotated -3 to -8 degrees. They are never used for scan or safety claims.

## 7. Components (class names in security-print.css)

- **Nav** `.top` with `.wm`, `.tag`, the account area, the mode switch and `nav a`, in that order in the markup. From 1000px the header is one row, as in the gallery: the wordmark and tag on the left, then the nav, the account area and the switch on the right (the nav moves up with `order`). Under 1000px the first row is the wordmark, the tag, the account area and the switch, and the nav is the row under it (the seven-link signed-in nav needs it), so keyboard focus moves left to right, then down, never back up the screen (WCAG 2.4.3). On hosted phone layouts the nav is a grid of three a row, each link as wide as its label (so the current page's underline is too). The current page gets `aria-current="page"` (2px accent underline). `.tag` is user data (account and email): Public Sans 13.5px in `ink-2`, as typed, never an upper-case mono kicker. A page with no switch (below) marks its header `.noswitch`, and the account area ends flush with the content edge.
- **Page grids** App pages use the contained `.wrap` (1200px, 32px gutters; 16px under 720px). Site-origin pages (system pages, listings, viewers) are full-bleed on the viewer bar's 18px gutter (12px under 720px): the site header, the listing body (at most 60rem), a system page's panel (at most 46rem) and the footer start on the same left edge as the viewer bar. The app's file workspace (`/v/`, `.page.wide`) and the encrypted-site wrapper frame site-origin files and are full-bleed the same way, header included.
- **File viewer frame** The app file viewer's preview frame (`.frame`) is backed by the mode's paper (white in Light), so a navigation inside it (a file in the tree, the password gate, an in-place switch) never flashes white in Dark while the next page loads. The site's own HTML still gets a white canvas in any mode (E2): the browser paints an opaque canvas for a light-scheme page in a dark-scheme frame. Every viewer page has one h1: a hidden one with the file name when the body has none. Inside the app's viewer the password gate says the preview shows the site as visitors see it, which is why its owner is asked for the password too.
- **Footer** `.foot` holds the wordmark, the domains, links and `.end`: API, llms.txt, MCP, Agent skill and Self-host, after any links of an embedding app (the hosted service puts Pricing first). `.trust` carries the line "Kofra does not scan files; open files only from people you trust." on every page that shows files; under a site-origin viewer it sits in the page's footer landmark.
- **Hero** `.hero` is a two-column grid: kicker, h1, `.lede`, an optional `.qs` numbered question list, and a `.plate` figure.
- **Section head** `.sec` with `.sec-h` holds `.num` (01, 02), an h2 and a one-line `p`.
- **Buttons** `.btn` is filled accent. Variants: `.ghost` (outline), `.quiet` (text), `.danger` (outline danger, for withdraw, revoke and delete), `.sm`, `.lg`. `[disabled]` sits at 45% opacity, `[aria-busy]` shows a progress cursor, and `:active` nudges 1px. `.linkbtn` is an underlined text button. `.btnrow` lays buttons out. On an accent bar (`.dlbar`, `.on-accent`) buttons invert to paper.
- **Inputs** `.label`, `.input` (text, select, textarea), `.hint`, `.msgline` and `.err`. Checkboxes and radios on app pages are drawn from the tokens (`field` fill, `edge` border, `accent` when checked) in both modes; forced colours get the native controls back. `aria-invalid="true"` draws a danger border. `.field` puts an input and a button in a row. `.otp` holds six one-digit cells. `.tog` is a checkbox label. `.dropzone` is a dashed perforation that tints on `.over` and on focus.
- **Segmented control** `.seg` with `aria-pressed`, for state and filter switches.
- **Tabs** `.tabs` with `role=tab` and `aria-selected`, plus `[role=tabpanel]`. Use them for CLI, MCP and API on the agent page, and for Files, Versions and Activity in the viewer.
- **Chips** `.chip` with `.accent`, `.ok`, `.warn`, `.danger` and `.solid`, grouped in `.chips`. Chips state facts: type and size, downloads left, live, expired, current version. There is never a "scanned", "clean" or "safe" chip.
- **Facts and key-value** `.facts` is the sender block line list, with icons in `accent`. `.kv` is a dt/dd grid.
- **Ledger table** `.table-wrap` with `.table`. Headers are mono kickers over an accent top rule, rows hover in `accent-wash`, and selected rows use `accent-tint`. `.num` right-aligns tabular numbers.
- **Cards** `.card` is paper-2 with a rule border. `.framed` adds the 6px inner line, and `.link` makes the whole card a link. `.cards` is an auto-fit grid. `.panel` is a surface with an accent border, for gates and forms. `.notes` holds three-column ruled notes.
- **Banners** `.honest` (or `.banner`) is the trust line, with a 3px accent left bar. `.banner.warn` and `.banner.danger` are coloured variants, and `.banner.annot` carries a vermilion annotation. `.inline-warn` is the acknowledge-and-proceed box for files that can run code. `.fwarn` is a one-line file warning. `.tip` is an aside with an icon.
- **Stub** `.stub` with `.tear` is the perforated ticket of terms: expiry in local time, downloads left, and the sender-is-told line.
- **Transfer document** `.doc-outer` › `.doc[data-micro]` › `.doc-in`, with `.doc-top` (wordmark, label, `.serial`), `.head-grid`, `.sender` and `.sealbox`. `.compare` shows the real seal beside a lookalike.
- **File rows** `.frow` holds `.thumb` (`.th-doc`, `.th-sheet`, `.th-folder`, a lite plate, or `.play` and `.tc` for video), `.fname`, `.fmeta`, `.sum` (a mini seal plus the short SHA-256 and a copy button), `.fact` (actions or `.got`) and `.prog`. `.frow.compact` is for dashboards. `.dlbar` is the download-all bar, `.hidden-list` with `.ghost-row` is the locked summary, and `.meter` shows quota or progress.
- **Receipt** `.receipt` with `.rc-head` (title and small seal), `.rc-meta`, `.rc-row` (full `.sha`) and `.rc-foot` (`.notified` plus actions), and `details.how` for checking a checksum. The print stylesheet prints the receipt cleanly.
- **Code** inline `code` and `kbd`. Inline code wraps only when one token is longer than the line, and a wrapped fragment keeps its padding (`box-decoration-break: clone`). A short token (a query, a scope, a secret's name) is `code.tok` and never wraps; a URL or command is `code.brk`, which wraps only after `/`, before `.` and at spaces (`<wbr>` between nowrap parts), never at a hyphen inside a name. File paths in ledgers wrap only after `/`. Inline code under 40 characters (a short URL, a scope, `GET /api/v1/billing/plan`) is `code.tok` and moves to the next line whole; only longer code wraps between its parts. A site's name is `code.tok` too (the claim page, with `#token=`), and an address is `code.brk` on site-origin pages as on app pages (the Report page), so a name never splits at its hyphen ("merry-" / "quartz-rf3bew"). The one exception is a name or URL part longer than the narrowest line (24 characters, a 320px phone): it may break inside itself rather than run off the screen. `.codeblock` holds `.codeblock-h` (a kicker and Copy) and a `pre`, with span classes `.p` (prompt, not selectable), `.c` (comment), `.s` (success output) and `.x` (error). A line wider than the block scrolls inside it, with a scroll shadow at the edge that has more (it moves with the content and is gone at the end). Commands people copy (the home page, the claim page, a new key's environment) are `pre.wrapped` and wrap, so the whole command shows; `pre.pick` selects all of it with one click on pages with no script (no Copy button there).
- **Versions** `.versions` is an ordered list: `.vn` is an italic serif number, the current version gets `aria-current="true"`, and older ones get a Restore action.
- **End states** `.state` holds a `.bigstamp` plus a heading, one line on what happened and the next action. Every system state on a site origin (404, 400, 410, 451, 500, 502, password, and EMPTY for a site with nothing published) is a `.state` panel with a mono kicker. Actions come in one order everywhere: the primary action first (Publish files, Try again), then Home as a ghost button; when Home is the only action it is the filled one (one emphasis for the single next action, on the app origin and on site origins alike). "Publish files" on an empty site is for its owner: it shows inside the app's file viewer, and a visitor gets Home. REPORT is the page the Report abuse link opens: the site's address and the instance's abuse contact (ABUSE_CONTACT), else who to tell. `.empty` is the dashed empty state for an empty list inside an app page (no sites, no keys), with one action.
- **Overlays** `dialog` with `.dlg` (and `.dlg.warn`), and the `.viewer-h/.viewer-b/.viewer-f` viewer. `.toast` uses `role=status`. `.mail` and `.browser` with `.urlbar` mock the email and the address bar.
- **Mode switch** `.k-mode-switch` is rendered by the server on the first header row of every app page, after the account area: `<form id="dw-mode" method="post" action="/__dropway/theme">` with three submit buttons (`name="theme"`, values auto, light, dark) and `aria-pressed` on the current one. With no script, the theme route answers 303 to `next#dw-mode-<choice>`, the id of an empty marker just before the pressed button (a fragment on the button itself would move the next Tab past it), so the next Tab lands on the button that was pressed. Exception, by design: pages that answer a POST and would lose their answer on a reload (an unlock error, a sign-in error after a POST) and pages that show a secret once (a new API key, an invite link, a new account's sign-in link) leave the switch out, and their header is `.noswitch`. The dashboard shows its secrets after the page has loaded (a new owner key on the sign-in page, a new API key, a new member's key, a claim token): while one is on the page the script hides the switch and marks the header `.noswitch` the same way, and the switch comes back when the secret goes. Confirmations that can be shown again are a GET after a redirect (POST, 303, GET: "Check your email" re-reads the address from a short-lived cookie, a used sign-in link is answered on the GET of the link) and keep the switch. Labels always show; icons from 720px. The nav takes its own row under it (so the header has the same rows before and after the account area fills in). The pressed label is bold, and every label reserves its bold width, so pressing a button never moves the switch. Hidden in print. Site-origin pages have no switch (they follow the device, or `?theme=`).

## 8. States

- Hover: accent-hover fills, an accent-wash behind ghost buttons and table rows, and an accent underline on nav links.
- Focus: a 2px `focus` outline with a 2px offset on every interactive element. Never remove it.
- Pressed and selected: `aria-pressed`, `aria-selected` or `aria-current` gives an accent fill or an underline. The selected state never relies on colour alone, because it always changes weight, fill or rule too.
- Disabled: 45 to 55% opacity and a not-allowed cursor.
- Invalid: a danger border, plus a `.msgline.err` that says what to do ("That password didn't work. 4 attempts left.").
- Loading: `.prog` and `.meter` bars, and buttons relabelled ("Downloading") with `aria-busy`.
- Transfer lifecycle: live, then expired, withdrawn, limit reached, taken down (451) or held. The two legal states give no detail and never blame the reader.
- Code-running file types (macros, executables) get one of three rotating warning designs, need an explicit acknowledgement, and the choice is recorded and shown to the sender.

## 9. Motion

The system is quiet and mechanical, like a printing press, with no bounce and no parallax.

- Seal draw: each path animates `stroke-dashoffset` from 1 to 0 over 0.6s on `cubic-bezier(.4,0,.2,1)`, with each band 40ms after the previous one. It runs only when the seal first appears or the ID changes.
- Toast: 0.2s opacity and translateY(20px to 0), auto-dismissed after about 4s.
- Buttons and the mode switch: 0.15s colour transitions. Progress bars use a linear width.
- Smooth scroll for in-page anchors.
- `prefers-reduced-motion: reduce` turns off the seal draw, smooth scroll and all transitions.

## 10. Content rules (owner decisions)

- Kofra does not scan files, ever. Never show scan states, "virus-free", "safe", "clean" or shield badges. Trust signals are: the verified sender, the exact type, the size, the SHA-256 checksum, the expiry, the download limit, report abuse, and the line "Kofra does not scan files; open files only from people you trust."
- The sender's name is the largest thing on a recipient page. The Kofra wordmark stays small. No ads, upsells or newsletter boxes.
- Times always show in the reader's time zone, with the zone named.
- Domains: the app is `kofra.app`, user sites are `<slug>.kofra.io`, and file downloads come from `files.kofra.io`.

## 11. Accessibility

- Both modes (and every archived colourway) pass WCAG 2.x AA, checked by `node contrast-check.mjs`. Text pairs are at least 4.5:1, and control borders, focus, stamps and seal lines at least 3:1. Decorative rules and frames are exempt and reported.
- Seals get `role="img"` and an `aria-label` that names the transfer or file. Microtext, bands and the lathe are `aria-hidden`.
- The mode switch is a group of three submit buttons with `aria-pressed`. Light or Dark persists in the `__Host-dw_theme` cookie; Auto removes it. `?theme=` applies to one response.
- Forced colours and reduced motion are handled as listed in section 3.
- Layouts reflow to one column at 720px with no horizontal scroll at 320px. Only `.table-wrap`, `pre` (reachable with the keyboard) and the file tree scroll inside themselves. A focusable `pre` or select-all block with a name has `role="region"`.
- Every page has one `<main id="dw-main">` and a "Skip to content" link first (site-origin viewers too, where it passes the viewer bar); every viewer with no visible h1 of its own (JSON, a table, an image, code, a PDF, an HTML page in the frame, the app's file viewer) names the file in a visually hidden h1.
- Text spacing (WCAG 1.4.12): with line height 1.5, letter spacing 0.12em, word spacing 0.16em and paragraph spacing 2em, no text is cut off that was not already: display headings wrap (no fixed-height lines), the viewer bar's path wraps (no ellipsis on the file name). The harness checks every screen this way (Light at 390 and 1440 px).
- A confirmation for an irreversible action opens on Cancel (or on its type-to-confirm field), never on its own button.
